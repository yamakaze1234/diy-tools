01先确认正在维护哪个环境

  1. 打开 腾讯云 CloudBase 控制台，选择部署工作台的腾讯云账号、地域和环境。记录环境名称与环境 ID，不要只凭名称判断。
  2. 请维护人员核对应用公开配置中的 envId 与所选环境 ID 完全一致；云函数 workbenchApi 的 WORKBENCH_ENV_ID 也应一致。公开配置来自 prototype/.env.local 中的 CLOUDBASE_PUBLIC_CONFIG；不要将整个配置文件或环境变量截图公开。
  3. 在该环境中定位 PostgreSQL 数据库、身份认证、云函数、云存储。控制台名称可能随版本调整，以功能名称及环境 ID 为准。
  4. 数据库中确认正式表 wa_workspaces、wa_members、wa_records、wa_changes、wa_mutations；素材桶为 workbench-assets。
正式工作台使用协议 2：workbenchApi → wa_api → wa_*。wb_api / wb_* 属于早期协议 1 验证链路，不能用其数量判断正式业务是否完整。工作区 ID 与 CloudBase 环境 ID 是两个不同的标识。

本机业务先保存到 SQLite，再提交云端。CloudBase 保存已提交记录和原始素材；Python 桌面版数据默认在 EXE 同级 data，源码运行时在 python-desktop/data；移动或升级时保留整个数据目录。测试或自定义启动目录以启动配置为准。

02成员开通、改名和停用

一个成员需要两层信息：身份认证账号负责登录，wa_members 成员记录负责进入工作区。仅创建账号还不能访问业务。

字段含义与维护口径
uid身份认证用户的实际 UID。精确复制，不使用用户名或昵称代替。
workspace_id加入的正式工作区，对应 wa_workspaces.id。
member_id稳定且唯一的内部成员编号；开通后保留，不随改名变化。
display_name操作人显示名。改名只修改此字段，不更换 UID 或成员编号。
activetrue 为启用，false 为停用；保留记录以便追溯历史。

新增成员

  1. 在环境的“身份认证 / 用户管理”中，通过当前已启用的用户名/密码方式创建成员账号；记录返回的 UID。若控制台无创建入口，交由维护人员使用该环境支持的认证管理接口开通。
  2. 在 PostgreSQL 的 public.wa_members 找到成员表。先查 UID 是否已存在、目标工作区是否正确；准备包含上述五个字段的新增记录，核对后由环境管理员保存。本文不提供可直接执行的写入 SQL。
  3. 用新账号登录工作台，核对右上角成员名。新电脑在“同步”中选择“接收已有云端数据”；云端已有资料时不重新发布本机空数据。
  4. 确认成员能接收该工作区数据，再交付账号。不要通过删除 RLS 策略或开放匿名权限解决登录问题。

角色与停用

当前应用成员拥有相同业务能力，wa_members 没有角色字段。腾讯云控制台管理员 / 协作者权限与工作台成员权限分别维护，普通工作台成员不需要控制台管理权限。

停用时，在成员表按准确 UID 定位，核对显示名与工作区后将 active 改为 false。若还需禁用认证账号，在身份认证用户管理中执行对应操作。再次调用业务接口时成员校验会拒绝访问；这不等于远程擦除已保存到其电脑的业务数据。重新启用保留原 UID、成员编号和工作区。

登录保留与账号切换

本次版本支持保留登录最多 7 天，刷新令牌不会延长这 7 天。到期或身份失效时使用原账号重新登录；退出登录后需重新登录。换账号前先处理原账号的待同步、结果待确认和冲突，避免由新账号提交旧账号草稿。不同工作区使用独立数据目录。

密码在身份认证入口重置；不要修改认证系统内部表。账号开通 / 停用属于管理员操作，业务配置修改与还原应在应用预览后确认。

03数据库检查：只读 SQL

在正确环境的 PostgreSQL SQL 编辑器执行。先查询工作区，再将示例中的 替换为已核对的工作区ID 改成其真实值。所有示例仅查询；没有权限时使用获授权的控制台管理员身份，不修改应用权限。

工作区与成员

SELECT id, name, head_seq, created_at
FROM public.wa_workspaces ORDER BY created_at;

SELECT uid, member_id, display_name, active
FROM public.wa_members
WHERE workspace_id = '替换为已核对的工作区ID'
ORDER BY display_name;

记录类型与数量

SELECT entity_type, count(*) AS record_count,
       max(updated_at) AS latest_update
FROM public.wa_records
WHERE workspace_id = '替换为已核对的工作区ID'
GROUP BY entity_type ORDER BY entity_type;
entity_type内容
configuration / component配置 / 共享人工成本与配件资料
source / template / settings输出源 / 模板 / 设置
gallery图库资料与素材引用
erp_chunk / erp_snapshot库存等 ERP 快照分块与发布记录
workspace_meta工作区初始化标记；正式入口使用 entity_id='root'

数量包含可能带删除标记的记录，不必与界面可见数量完全相等。不要按一条记录对应一个商品、一个分块对应一个库存项目推算。

最近提交与日志连续性

SELECT seq, entity_type, entity_id, version,
       updated_by, updated_at, mutation_id
FROM public.wa_changes
WHERE workspace_id = '替换为已核对的工作区ID'
ORDER BY seq DESC LIMIT 30;

SELECT w.id, w.head_seq, coalesce(max(c.seq), 0) AS latest_seq,
       count(c.seq) AS retained_change_count
FROM public.wa_workspaces w
LEFT JOIN public.wa_changes c ON c.workspace_id = w.id
WHERE w.id = '替换为已核对的工作区ID'
GROUP BY w.id, w.head_seq;

当前通过保留的变更日志重放初始化。head_seq 与最大日志序号不一致时交给维护人员调查；不要手工改序号。wa_mutations 是幂等回执，不能当作临时表清空；直接改 wa_records.data 不会自动生成完整变更、版本和回执。

04同步不动、冲突和结果待确认

编辑落盘后约 500ms 触发同步，正常登录且启用同步时约每 10 秒检查更新。网络请求、素材上传、排队或失败会增加等待时间；“已与云端同步”表示当前本机提交已确认，不代表其他电脑同时刷新。

现象按顺序处理
本地已保存 / 待同步打开右上角“同步”，确认已登录、已启用、没有暂停，点击立即同步；观察待处理数量与错误。
登录失败 / UNAUTHENTICATED确认环境和当前用户名密码，重新登录；检查认证账号状态。保留原账号草稿。
NOT_MEMBER / 无工作区权限核对实际 UID 对应的 wa_members、active 与工作区。仅有认证账号不够。
SERVER_CONFIG核对云函数的 WORKBENCH_ENV_ID；不能通过重置本机数据修复云端配置。
DATABASE_UNAVAILABLE / RETRYABLE / 网络超时检查环境可用性和云函数日志，恢复网络后由原同步队列继续。结果未确认时不要清空队列或重新制造一笔相同业务提交。
存在冲突在同步面板查看冲突，核对记录、字段、基础值、我的值和云端值；选择保留哪一边。解决后再同步，其他人又修改时可能再次产生冲突。
UPGRADE_REQUIRED确认桌面与云端协议版本，按升级流程更新；正式版使用协议 2。
首次接收为空或未完成检查云端初始化标记、同步错误和原始素材状态；完成接收后再编辑。不要把“未下载完成”误判为数据丢失。
同步失败时先下载同步备份。不要删除 workspace.sqlite、待提交队列、wa_changes 或回执来“强制刷新”；这些信息用于继续同步和确认此前提交结果。

05备份与恢复：选择对应范围

日常找回

本机历史版本

打开“历史版本”（也可从同步面板进入），选择时间 → 查看差异 → 核对影响 → “备份当前并还原”。还原形成新的版本，并按正常流程参与同步。

从本次版本开始记录，每次业务保存 / 云端接收形成本机完整业务状态快照，最多保留 100 份。不追溯升级前未记录的历史，不包含原图字节，也不是全员共用的云端历史列表。

换机 / 故障恢复

同步备份 + 原始素材

在“同步”下载同步备份 JSON，记录时间与工作区。它包括记录、草稿、业务状态及未确认提交，不包含密码和原图字节。

关闭桌面程序后复制完整 data 目录可保留本机文件；完整离线恢复需同时保留 data/assets。只复制运行中的 SQLite 主文件可能遗漏尚未合并的数据。

维护人员：同步备份恢复到新目录

使用兼容当前项目的 Node 环境，在 prototype 目录执行以下命令。目标必须为新的数据目录；脚本拒绝覆盖已有同步库或 state.json。

node restore-sync.mjs 'D:/备份/工作台同步备份.json' 'D:/工作/恢复工作台'
$env:DATA_DIR='D:/工作/恢复工作台'
$env:PORT='4191'
node server.mjs

先核对恢复的记录、未确认提交与素材，使用原账号登录。带有待提交内容的恢复副本联网后可能继续同步，不能与原目录同时运行。要演练还原，使用隔离测试环境；不要把本机恢复误当成正式云端回滚。

云端灾难备份

本项目尚未实现云端定期全量备份和自动恢复编排。维护人员需在当前 PostgreSQL 控制台核实套餐可用的备份 / 恢复能力及保留期，准备包含五张 wa_* 表、函数 / 策略和私有原始素材的配套恢复方案，在隔离环境验证一致性后再用于正式环境。单独导出配置表不能恢复成员、提交序号和幂等回执。

06原始素材、缺图和回收

在云存储中定位私有桶 workbench-assets。对象路径为 工作区ID/内容SHA256.png 或 .jpg；工作台引用为 /uploads/内容SHA256.扩展名。新电脑按需下载，客户端核对文件内容与哈希。

  1. 缺图时先确认已登录并且工作区正确，检查本机 data/assets 是否已有对应文件。
  2. 再到私有桶查找完整路径，核对对象是否存在以及访问权限。403 优先查账号成员状态 / 存储策略，404 优先查路径和上传是否完成。
  3. 文件存在但提示校验失败时，保留错误信息，检查原文件与哈希。不要直接覆盖同名哈希对象；通过工作台重新上传正确原图，更新需要修改的引用。

图库删除进入应用回收站，已有配置和模板可能继续引用原图。当前没有自动清理云端原图的机制；不能按上传时间直接删除。生成的配置 PNG、SKU 图与 ZIP 留在本机，不作为云端素材备份的一部分。

素材访问沿用成员权限，相关辅助函数为 wa_storage_member。不要将私有桶改成公开读写来处理单个成员缺图。

07云函数、错误与日志定位

控制台 → 当前环境 → 云函数 → workbenchApi → 详情 → 日志 / 监控。按故障发生时间缩小范围，并记录请求 ID、错误码、函数版本及发生设备。官方说明见 云函数监控。

核对项本项目实际行为
函数类型与入口Node.js 事件函数，代码 cloud/functions/workbenchApi/index.js，导出 main。客户端经事件函数 HTTP API 调用，不改成 HTTP 函数入参。
环境变量WORKBENCH_ENV_ID 指向相同 CloudBase 环境。
身份用户访问令牌传递至 PostgreSQL RPC；数据库通过 auth.uid() 和启用的成员记录检查身份。客户端填写的操作人名称不能授予权限。
路由protocolVersion === 2 调用 wa_api；其它路径进入 wb_api 后仍需通过对应协议检查。
超时与体积函数内数据库请求等待上限 15 秒；客户端请求等待上限 30 秒。函数请求内容长度设有 600000 上限；数据库单条记录另有 250000 字节限制。

同时看调用次数、错误数与耗时。业务可能以 ok:false 返回而 HTTP 本身成功，仅看平台“调用成功”不足以确认同步完成。函数当前不会主动打印完整业务请求；日志为空不代表没有业务错误，应结合工作台错误码、时间与数据库最新提交核对。

反馈问题只需时间、错误码、请求 ID 和影响范围。不要收集密码、accessToken、Authorization、Cookie 或整份环境变量。

08桌面升级与数据库迁移

  1. 收集当前版本、云端环境与工作区，确认没有未解决冲突或结果待确认提交。下载同步备份，关闭程序后备份完整数据目录。
  2. 桌面升级替换 EXE，保留 data。不要用空目录覆盖已有业务目录，也不要打包真实数据与凭据分发。
  3. 数据库迁移由维护人员根据已部署历史逐个核对，仅执行未部署且已审阅的迁移；在隔离环境验证后安排正式变更。本项目早期迁移包含 CREATE TABLE，不能无差别重复运行。
  4. 如只改变桌面功能，不因版本发布而自动重跑云端迁移。涉及云函数 / SQL 变更时协调协议兼容和客户端升级顺序。
  5. 升级后验证登录、成员名、配置数量、原图显示、同步状态；在隔离数据中验证新增 / 修改、冲突、备份恢复。再安排两台真实电脑确认接收更新。

回退桌面程序前先确认新旧数据格式兼容。云端回退不能只恢复旧 EXE；必须根据实际变更设计前向修复或一致性恢复。

09公司 SQL 库存：独立只读来源

公司数据库采集在本机执行，与 CloudBase 多人同步不同。SQL 只读采集后，先在工作台查看差异，确认后更新库存；公司 SQL 按“公司大库”的“库存成本”更新本机单件 ERP 成本与分库可销数，保留人工含税成本；ERP 成本和可销数不再上传云端。

  1. 由数据库维护人员提供实际数据库类型、地址、数据库名和只读账号；确认当前电脑能访问公司网络。连接密码留在采集电脑，不上传多人工作区。
  2. 查询必须明确账套 / 仓库范围为“公司大库”，精确返回真实 goodsId 和约定的可销库存字段。无真实 ID、重复 ID、字段口径不明时先修复，不按名称猜配件。
  3. 在连接设置中配置本机采集来源，执行只读采集；核对来源、时间、总数、匹配 / 未匹配及差异。确认预览后才应用。
  4. 采集失败或不完整时保留上次有效库存及其时间；每位成员在自己的电脑连接 SQL 并确认应用；ERP 成本与可销数各机独立，其他电脑需自行读取。

公司数据库实连结果需以当前现场验证为准。本文没有访问公司 SQL，也不提供猜测的表名或字段映射；“脚本抓取”仍按其既有库存 / ERP 采集规则使用。

10基础维护节奏与费用

频率 / 时机具体动作与完成标志
每日首次使用确认成员与工作区、同步状态、库存成功时间；存在冲突或离线时先处理。
每周下载同步备份并保留原始素材副本；检查成员启停、函数错误趋势、数据库 / 存储用量和近期账单。
升级 / 批量修改前保留完整备份，核对修改预览与影响范围；不要把“本机保存成功”当作云端确认。
人员变化开通或停用应用成员，分别维护腾讯云控制台协作者；保留成员历史标识。
定期恢复演练在隔离目录 / 测试环境恢复备份，核对记录和原图，记录用时与缺失项。

在环境的用量 / 套餐入口查看数据库、存储、认证与函数资源使用，在腾讯云费用中心核对账单和续费状态。4～5 个工作台用户共用同一环境；应用认证用户额度与控制台协作者额度分别计算。价格、套餐额度和保留期以当前控制台为准。

10 秒轮询可能增加调用次数。出现费用上升时，先按日期对比调用量、素材下载流量、数据库增长和日志用量，再判断原因；不要通过清空日志表或关闭身份校验降低费用。

依据与适用边界

本手册根据项目代码与迁移文件编写，未读取账号凭据或业务记录，未访问或修改正式数据库、未部署云函数。控制台导航按功能名称描述；未声称当前环境已完成备份配置或本次公司 SQL 实连。

本次新增的 7 天登录、500ms / 10 秒同步、本机历史版本和公司 SQL 预览流程应与随附桌面版本一起使用；旧版行为以旧版界面为准。
