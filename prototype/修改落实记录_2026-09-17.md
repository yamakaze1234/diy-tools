## 0.2.19：SQL 应用兼容修复与本机连接保存

已同步后仍出现 `编辑期间同一字段已变化：chunks`，原因是相同库存的行顺序与属性顺序改变，导致旧分块摘要不同。新版统一分块顺序，并校验旧快照的完整内容后兼容转换；真实库存内容冲突仍被拦截。首次转换将完整补齐引用分块，不清空数据。

勾选“在本机加密保存并自动填入”后，点击“读取并预览”保存连接设置和密码。桌面端使用 Windows 用户保护的 Electron safeStorage，按工作区与成员分别保存到 data/sql-credentials，排除在业务状态与云同步之外。可点“清除本机保存的连接”清除。不同电脑仍需各自输入。

库存预览固定五列并每页显示 100 条，确认按钮应用整个预览。原本空错误容器自动隐藏的修复保留。

## 0.2.20：ERP 数据仅本机、SQL 单件成本与配件描述

ERP 成本与可销数仅在本机保存。每位成员点击“ERP同步”，使用本机加密保存的 SQL 连接读取公司大库；“库存成本”字段经用户确认是单件 ERP 成本，“分库可销数”为可销库存。先预览原/新成本和库存再确认，人工核算价保留。

云端继续同步配置、人工核算价、输出源、店铺设置、模板和图库；配置及模板内的 ERP 缓存字段也不上传。旧版分块上传队列升级时先自动本机备份再停用；旧云端库存记录不再用于本机业务数据。已有云端历史记录未执行删除。所有成员应使用 0.2.20，旧版客户端仍遵循旧规则。

配件选择优先显示本店输出源优化描述，ERP 原名仅作为搜索别名和缺少描述时的备用。单件成本按 goods_id 单独读取，不覆盖优化名称。不自动替换已保存配置的自定义文字，也不改动粘贴导入的原始名称约定。

验证：157 项自动检查；现有 12,702 条库存的只读内存迁移与 SQL 更新模拟，ERP 更新新增云端提交为 0，人工价保留。桌面验收记录见 verification/results/auth-desktop-local.json。

## 0.2.21：新电脑同步状态与卡顿修复

- SQL 同步与脚本采集状态分别处理。脚本遗留的“等待 ERP 连接”不再覆盖 SQL 完成状态或禁用 SQL 按钮；新电脑默认打开 SQL，可在连接设置显式切换脚本。
- 全新空白电脑登录已有工作区后自动接收云端资料。有本机业务数据的电脑仍通过“接收已有云端数据”确认并备份，避免自动替换。
- 云端下载显示当前序号 / 总序号；首次同步尚未完成时不会提前显示“已同步”。
- 活动记录由逐条整理改为每页合并一次，状态计数缓存，无变化时不再重建和下载整份业务状态；输入时的图片预览增加短暂合并等待。
- SQL 表单区分“正在保存本机配置”与“正在连接 SQL”，读取超过 90 秒给出超时提示并恢复按钮。

本机合成 2000 条记录验证：第 20 页处理从约 372ms 降至 8ms（仅本地处理，不含网络）；160 项自动检查通过。新电脑桌面场景见 verification/results/new-pc-desktop.json。
