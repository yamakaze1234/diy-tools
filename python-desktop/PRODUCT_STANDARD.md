# 商品标准 JSON

依据 [CoreHub/pypkgs PR #13](https://gitea.cq360.top/CoreHub/pypkgs/pulls/13)，核对版本 `b550c733a159472724cb79f99e4d6790edcac090`。

商品业务数据、文件导出及 ERP 查询结果共用 `prototype/product-standard.js` 的字段契约。工作台原有配置、图片、样式、历史版本继续保存在原数据结构中；标准商品文件是随本机保存、云端接收、历史还原同步生成的业务视图。不要直接修改生成文件来编辑工作台。

## 实际文件

当前数据目录下 `products-standard/index.json` 列出有效商品链接及对应的 `.json` 文件。每个链接一个标准 JSON，文件名由本地店铺和链接标识生成，不受商品改名影响。

- 外层：`店铺ID`、`店铺`、`数据来源`、`状态`、`网店类别`、`SPU编码`、`SPU名称`、`备注`。
- `SKU`：以平台 SKU 编码为键。内容含 SKU 名称、价格、库存、更新时间、ERP 套餐 `goods_id`、ERP 商品名称、图片网址、商品网址、关联更新时间。
- `SKU明细`：从当前**实际配置**生成，仅有 `goods_id`、`n`、`商品名称`、`简称`。`n` 为正整数，名称优先使用本店输出源优化名称；商品名称保留 ERP 原名。特殊无 ID 配件不参与 BOM。
- `SKU价格` 为定价，即到手价加本店优惠券。`SKU库存` 保留上次查询的网店库存；不会用配件的 ERP 可销库存替代。
- 商品 URL、图片 URL 保持 SKU 维度。远程图片 URL 不会自动覆盖海报素材。
- 未绑定的 ERP 店铺 ID / SPU / 配件 ID 为 `null`。没有有效 SKU 编码的配置无法作为 SKU 键，保留在原工作台数据中，并在索引中列出待补项；不编造平台编号。

索引的 `ready` 只表示匹配所需的基础标识与实际 BOM 完整，不表示已经执行 ERP 匹配，也不表示库存实时或关联套餐仍与当前配件一致。ERP 套餐 `goods_id` 为上次查询的关联结果；更换实际配件不会伪造新的 ERP 关联。

将来的匹配入口应优先读取登录保护的 `GET /api/products/standard`，它根据当前已保存状态即时生成数据。离线读取必须以索引为入口，核验 `sourceHash`、`revision`、文件 `sha256` 和 `ready`，忽略索引之外的历史文件；不能扫描目录直接执行匹配。配置保存期间多个文件可能处于更新中，校验失败时应重新读取。

## 工作台入口

右上角 **商品同步**：ERP 刷新并查询、标准 JSON 导入预览、标准 JSON 导出。店铺设置可维护本地店铺与 ERP 店铺 ID 的对应关系。

用户确认的默认 ERP 店铺 ID：英特尔 `76`、技嘉 `32`、乔思伯 `33`。仅在没有保存对应字段时补入默认值；用户已经保存的映射或明确清空的映射继续保留。

查询通过新版 `workbench-erp.user.js` 0.2.0 使用浏览器已有 ERP 登录。脚本右下角按钮连接商品查询，只核对顶栏账号姓名；库存成本连接仍可从脚本管理器菜单进入，库存同步保留原 SQL / 脚本两种来源。

查询顺序与 PR 一致：指定店铺/SPU 刷新网店商品 → 完整分页查询 → 筛选上架 SKU → 按关联 goods_id 查询并复用套餐明细。没有关联或空明细返回 `[]`。本机回传校验账号、页面、任务令牌、期限、店铺和 SPU。

预览确认后才修改工作台。未填写 SKU 的旧配置须由用户选择对应关系；缺少配件明细时保留原实际配置，未返回 SKU 也保留。导入更新价格为可选项，未勾选时原价保留。已有海报配件、样式、加购、自定义简称保留。

本次未实现 ERP 套餐创建、匹配、绑定或配置写回。
