# 配置工作台 · 轻量网页原型

包含独立示例原型 `index.html` 和成员登录云端版 `cloud.html`。示例数据与真实工作区使用独立存储，不会把示例内容上传云端。云端版直接调用现有 CloudBase `workbenchApi` 协议 v2。

## 打开使用

- 直接用浏览器打开 `dist/index.html`；这是已打包的单文件页面，适合复制给 Mac / Linux 同事查看。
- 或在本目录运行 `node server.mjs`，打开 `http://127.0.0.1:4196`。服务器只提供原型页面，不开放项目其他文件。
- 数据保存在当前浏览器的独立 localStorage 键 `diy-web-lite-prototype-v1`。文件打开与 HTTP 打开的存储独立；清除浏览器数据会移除原型内容。顶部可导出原型数据备份（此版未提供导入）。

## 已实现的体验

1. 按店铺 → 分类 → 商品链接 → 配置导航，查看到手价、定价、ERP / 核算成本和利润；支持搜索、筛选和排序。
2. 新增商品链接和空白配置；更换配件、调整数量、填写 SKU、到手价和分期，即时重算利润与库存可配台数。
3. 每店独立模板分类。支持逐套勾选、多选、整组全选、全部选择，添加到指定链接；创建副本，不修改源模板，SKU 留空。
4. 已有配置用单套模板替换时先显示配件差异；只替换实际配件，保留当前链接、SKU、名称、售价、分期和图片展示字段。
5. 当前单套或当前商品整组配置可以存为模板。模板支持查看及重命名。
6. 原型草稿随输入保存在当前浏览器，明确“保存配置”后提交为已保存版本；可撤销未保存修改。支持 Ctrl/Cmd+S。
7. 人工核算价集中维护并显示保存影响；修改影响所有引用相同商品 ID 的原型配置。
8. 右上角集中提供「ERP 同步」与「云端同步」。示例版 ERP 为明确标注的固定示例快照；云端版 ERP 脚本尚未接入，不显示演示价格或库存。云端入口可进入真实工作区。

## 0.2 输出源与加购维护

- 进入「核算价格」，选择店铺 → 搜索配件 →「维护输出源」。可编辑本店显示名称、升级说明、新增多个加购方案、加购总价、替换数量和组合商品。核算价依然三店共用，加购按店铺保存。
- 每个方案支持「替换原配件」或「额外加装」，关联一个或多个准确商品 ID，各自设置数量；支持单独控制是否在配件行展示。保存前显示修改前后内容和影响范围。
- 编辑配置时，配件型号下方直接显示对应加购，点击「编辑加购」可另存为当前配置草稿。全店输出源更新不覆盖已自定义的配置；「恢复跟随输出源」可以恢复继承。
- 差价直接复用现有工作台 `prototype/addon-data.js`：原配件成本 × 替换数量 + 加购总价 − 新组合成本。额外加装不抵扣原成本，组合只收一次加购总价。ERP、核算分别检查，缺失成本显示待补充。
- 加购只是可选报价，不自动修改基础整机到手价、配件成本和利润。实际成交的升级配置需要另行修改实际配件。
- 新存模板保存加购快照，模板副本可以继续编辑。更换配件时清除旧商品自定义加购，避免错误绑定。
- 原型升级仅追加输出源数据，保留已有配置、草稿、价格、模板和日志；使用原来的页面地址刷新即可，不能清除浏览器存储。

## 业务口径

直接复用 `prototype/core.js` 的 totals 和 `prototype/pricing.js`，构建时打包入单文件。

- 定价 = 到手价 + 店铺优惠券。
- ERP 利润 = 到手价 × 98% − ERP 成本 − 分期费。
- 核算利润 = 到手价 −（核算成本 + 到手价 × 4% + 100）− 分期费。
- 12 / 24 期分别按到手价的 6% / 10% 扣费；分类名称本身不改变分期。
- 按实际配件和数量核算。缺失成本不当零成本；两个成本口径分别判断完整性。库存未知时不推断可配台数；重复商品合并需求后计算库存。

## 0.3 云端版

打开 `http://127.0.0.1:4196/cloud.html`，使用现有工作台成员账号登录。首次只拉取已发布的工作区，不创建初始工作区、不上传示例记录。成员权限仍由现有云端接口校验。未增加匿名登录、注册或新的云端数据库。

- 网页保存 → 右上角「云端同步」→「立即同步」→ 本地工作台执行同步，即可接收双方的修改。未保存的配置草稿需先保存或撤销。
- 输出源按原始 `sourceId` 区分；同一商品多个来源逐行展示，按店铺维护。名称、升级说明、加购价、组合商品数量和显示选择转换为桌面原生字段。原生 choice 数据在可表达的情况下保留其结构，组合使用已有 variants/items 格式。
- 跟随来源的网页配置保存对应加购；独立配置以原生 `configuration.addons` 和配件覆盖信息保存。桌面端后续修改原生加购时优先采用桌面新值，不保留过时的覆盖信息。
- 已保存配置、模板、核算价、优惠券也按原始记录 ID 同步。未编辑的图片、展示配件、画布、质保及其他字段保留。未创建配置的空链接暂留在浏览器，第一套配置保存后随配置上传。
- ERP 成本与库存不属于现有云同步协议，云端版显示未知。ERP 浏览器脚本接入是后续工作，不能用云端人工核算价冒充 ERP 成本。
- 云端真实数据使用 IndexedDB `diy-web-lite-cloud` / `workspaces`，按环境、工作区、成员分开。旧 localStorage 云端缓存会自动复制到 IndexedDB，并从原游标继续，旧缓存保留。示例原型仍使用原来的 localStorage 键。
- 视图、已保存记录、版本、冲突和待确认请求在同一个数据库事务保存；请求落盘后才联网。失败重试沿用原 mutationId。每个写入事务检查 revision，多窗口冲突时停止保存，保留当前副本用于导出。
- 同字段或删除并发需要比较并选择版本；不同字段可合并。断网和权限错误保留待确认队列，不报告同步成功。记录删除作为原生软删除接收，网页不提供整库覆盖或硬删除。
- 本次桌面源码 `prototype/addon-data.js` / `source.js` 增加了额外加装的方式透传和零原件抵扣。旧桌面 EXE 需要更新后才能正确核算这个新方式；本次没有打包或替换已安装的 EXE。普通替换加购、组合商品沿用现有协议。

构建从本目录 `.env.local` 的 `CLOUDBASE_PUBLIC_CONFIG` 读取白名单字段 `envId`、`region`、`functionName`、公开 `accessKey`；不打包用户密码、用户令牌、业务记录或管理密钥。可参考本地工作台的公开配置设置，不复制整个环境文件。云端版须通过 HTTP(S) 打开；示例版仍可直接打开单文件。

`node tests/cloud-browser.mjs` 使用隔离认证与协议端点验证真实页面代码，覆盖成员门禁、首次只拉取、双向字段、草稿、冲突、丢回执重试、超过 7 MB 的工作区、手机与多窗口。不向生产云端写测试记录。`node --test tests/cloud-sync.test.mjs` 验证记录往返、未知字段、模板、缺失成本和先落盘后联网。

本地已完成代码接入与隔离验证；用户已于本次会话确认真实成员登录并看到工作区；生产双端写入与旧 EXE 升级仍未执行。未发布公网网页，Mac / Linux 实机未验收。


## 大数据量性能优化

- 总览、核算价格和模板选择每页最多 50 项；配件选择每页 60 项。搜索覆盖全部数据，翻页不改变商品 ID / 输出源 ID，也不丢失模板勾选。加购商品选择先搜索，再显示最多 60 个结果，并始终保留已选商品。
- 云端商品链接默认折叠，折叠分支不创建配置 DOM；同一链接超过 60 套时目录和编辑页支持分段切换。模板卡片只预览前 5 套。
- 商品、来源和云端记录按 ID 建索引；总览共享成本索引和本轮利润计算结果，避免逐条扫描整个目录。搜索在大数据量下合并连续输入。
- 云端输入只保存草稿增量，工作区大快照保留。IndexedDB 的 `workspaces` 继续使用原字符串键存完整状态，另用 `[key, 'drafts']` 和 `[key, 'revision']` 两个数组键保存草稿及版本；必须通过 `openCloudStorage().get(key)` 合并读取。正式保存原子更新完整状态、清除草稿增量并推进同一版本保护；旧数据无需清空。
- 配置目录与总览醒目展示「配置编号：CPU + 显卡 + 内存 + 硬盘」，完整名称可悬停查看，摘要不改动保存的业务字段。

`node tests/performance-browser.mjs` 验证 5,018 商品 / 15,054 输出源的分页、全量搜索及加购准确绑定。

`node tests/cloud-performance-browser.mjs` 用真实云端页面代码、隔离认证及本地测试数据检查 26 MB / 15,003 输出源 / 1,001 配置工作区，覆盖日常耗时、分页模板勾选、草稿刷新恢复、全量保存合并、多窗口冲突保护。不向生产云端写入。

本机一次测试：核算价格 26 ms，总览切换 22 ms，编辑页 30 ms，配件选择 58 ms，输入及草稿落盘 84 ms，正式保存 535 ms。完整结果见 `verification/cloud-performance.json`。这是隔离压力测试，不代表用户设备、生产网络同步或首次下载耗时。

## 配件批量维护

总览和编辑页提供“批量修改 / 添加配件”。支持当前链接、本店全部配置、跨链接逐套勾选，搜索结果跨页全选；普通配件按商品 ID 匹配，特殊配件按名称匹配。替换数量留空保留原数量，添加检查 14 个 ERP 槽位，已占用槽位拒绝覆盖。预览分页展示修改前后内容，确认后统一保存选中配置及其已有草稿，云端仍手动同步。

单套添加只能选择未占用的工作台槽位，可设置数量并选择普通 / 特殊配件。批量新配件搜索结果及选中详情显示可销库存、ERP 单价和核算单价；未知库存不当零，特殊配件库存不适用。尚未导入 ERP 快照的商品显示未知。

`node --test tests/batch-parts.test.mjs` 检查数量、来源、自定义加购清理、槽位、店铺隔离及原生记录兼容；`node tests/batch-browser.mjs` 检查跨页勾选、预览、精确目标保存、占位拦截、刷新恢复与手机布局。

## ERP 同步：网页脚本 / SQL（本机连接）

右上角“ERP 同步”选择来源，两者均先预览差异再应用，不改人工核算价。

- 网页脚本：下载此页面提供的新版工作台脚本，沿用原 ERP 账号、公司大库、成本列与完整分页校验。点击 ERP 页面“导出网页版库存”，将 JSON 快照直接导入网页。脚本不回传公司内网服务；原 Windows 工作台采集通道保持不变。纯静态托管也支持文件导入。
- SQL：在能访问公司数据库的 Mac / Linux / Windows 电脑上运行本地连接程序，访问 `http://127.0.0.1:4196/cloud.html`。填写公司 SQL 地址、数据库、只读账号、密码；执行的只有工作台现有两条固定 SELECT 查询，读取公司大库分库可销数、库存成本。密码只用于本次连接，不保存在文件或浏览器中。静态托管页面不会接收或转发 SQL 账号密码。
- 运行：安装 Node.js 22 或更新受支持版本，确保已有 `prototype` 依赖包含 `mssql`（首次可执行 `npm --prefix prototype ci`），在项目根目录执行 `node web-lite/server.mjs`。当前端口是 4196；服务固定监听 127.0.0.1，不开放局域网访问，不需要公司中转服务器。
- SQL 快照缓存默认保存在 `web-lite/local-cache/inventory/`，按成员和工作区隔离，可用 `INVENTORY_CACHE_DIR` 指定文件夹。缓存只含库存、ERP 成本及来源，不含 SQL 密码。读取缓存后仍需预览确认；数据库查询失败不替换原缓存。
- ERP 快照应用在本浏览器。云端同步后及刷新后保留；不上传至配置云端。完整批次缺项及未匹配商品显示未知，不推断为零库存。

验证：`node --test web-lite/tests/erp-data.test.mjs web-lite/tests/inventory-service.test.mjs prototype/tests/erp-sync.test.mjs prototype/tests/sql-sync.test.mjs`；`node web-lite/tests/erp-browser.mjs`。SQL 驱动与页面均使用工作台现有实现；本次隔离测试不代表已经连接公司实际数据库或真实 ERP 页面。
